# 引用块背景断开（段间白缝）修复 — 设计文档

**日期**: 2026-10-09
**版本**: v1.7.4 → v1.7.5

## 1. 背景

多段引用块（Markdown `>` 连续多段）渲染时，每段有自己的浅灰背景，但**段与段之间出现白色断开**。用户截图反馈该视觉问题。

根因（源自 `2026-09-24-blockquote-style-design.md` 已记录的技术限制）：Qt 富文本引擎**不渲染 table/td 的 background-color**，引用块的浅灰背景只能放在每个段落 `<p>` 的 block 层（`td.md-quote-cell p { background-color: #e8e8e8 }`）。而段落之间有 margin 外边距，**margin 区域不绘制 block 背景**，于是多段引用在段间露出白色缝隙。

## 2. 目标行为

| 场景 | 当前 | 目标 |
|------|------|------|
| 多段引用 `> p1` + `> p2` | 各段背景，段间白缝 | 各段背景连成一片（无白缝） |
| 单段引用 | 浅灰背景 + 左竖线 | 不变 |
| 嵌套引用 | 内外层各自背景/竖线 | 不变 |
| 引用内嵌表格/列表 | 表格保持 1px 全边框 | 不变 |

## 3. 技术方案

### 3.1 改动点（仅 `md_viewer.py`）

`wrap_html()` 的 `<style>` 中，`td.md-quote-cell p` 规则追加 `margin: 0;`：

```css
td.md-quote-cell p {
    background-color: #e8e8e8;
    margin: 0;
}
```

即从：

```css
td.md-quote-cell p {
    background-color: #e8e8e8;
}
```

改为上面的两行形式（仅新增 `margin: 0;` 一行）。

### 3.2 方案验证（offscreen 像素级实验）

| 写法 | 两段间白缝行数 |
|------|--------------|
| 默认 margin（现状） | 20 行白缝 |
| `margin: 0`（方案） | **0 行白缝（背景连续）** |
| `margin: 0; padding: 6px 0` | padding 被 Qt 忽略，与 margin:0 高度一致 |
| `margin: 0; border-bottom: 8px` | border 被 Qt 忽略，与 margin:0 高度一致 |

结论：`margin: 0` 是唯一能消除白缝的可行写法；Qt 不解析 p 的 `padding`/`border`，无法用它们补偿段间留白。

### 3.3 权衡

修复后多段引用的段落间**紧贴排列**（段间仅 1.6 倍行距分隔，即 body 的 `line-height: 1.6`），呈现为“整块连续背景”的形态，与主流 Markdown 渲染（如 GitHub）一致。这是 Qt 引擎限制下的最优解。

## 4. 边界情况

| 场景 | 预期行为 |
|------|---------|
| 单段引用 | 行为不变（margin:0 对单段无感知变化） |
| 多段引用 | 背景连成一片 |
| 嵌套引用（`>>`） | 内外层段落各自 `margin: 0`，各自背景连续 |
| 引用内嵌 markdown 表格 | 不受影响（表格 td 非 p，选择器不命中） |
| 引用内含列表/代码块 | 不受影响（列表/代码块元素非 p；原有“列表/代码块无引用背景”的已知局限不变） |
| 无引用的文档 | CSS 变更零影响 |

## 9. 补充修复（2026-10-09 追加）：空灰条

`margin: 0` 只消除了段间白缝。用户复测发现仍有「空灰条」——有背景无文字的灰色横条，位于多段引用段落之间与引用块末尾。

### 9.1 根因

书中的引用块是**连续 `>` 行**（空行也带 `>`），python-markdown 将其整体合并处理。空灰条有两个来源：

1. **段间空灰条**：`_inject_anchors` 给空引用行 `>` 也注入零宽锚点 `<a id="popup-anchor-N"></a>`，使空行从「段落分隔符」变成「有内容的行」，破坏段落分隔。多段引用被合并成一个 `<p>`，空行处形成「锚点 + 换行」的空行盒——占一行高度、带背景、无文字。

2. **末尾空灰条**：引用块末尾的空引用行 `>` 被 lazy continuation 并入最后一段，`nl2br` 将其转为段落末尾的悬空 `<br />`（Qt 中为 block 内换行符 U+2028），渲染为末尾空行盒。此为 nl2br 原生行为（无锚点管线同样复现）。

### 9.2 追加修复

**A. `_inject_anchors` 跳过空引用行**（消除段间空灰条）：引用行内容去掉全角/半角空格与 tab 后为空时，不注锚、原样保留，恢复其段落分隔符作用。

**B. 删除段落末尾悬空 `<br />`**（消除末尾空灰条）：HTML 后处理 `re.sub(r'<br />\s*</p>', '</p>', html)`。正常段落末尾本无 br，删除无副作用。

### 9.3 测试

- 新增单元测试：`_inject_anchors` 对空引用行（`> `、`>　`）不注锚、保持原样；对含内容引用行仍注锚。
- 新增单元测试：段落末尾悬空 `<br />` 被删除，正文段落内换行 `<br />` 不受影响。
- 现有 `test_inject_anchors.py`、`test_quote_rendering.py` 回归。

## 10. 补充修复（2026-10-09 追加）：代码块行间背景断开

用户截图红框内容实为**代码块**（``` 围栏），非引用块。此前修复未命中。

### 10.1 根因

`wrap_html()` 的 `body { line-height: 1.6 }` 使 Qt 为**每个 block 分配 1.6 倍字体行高的布局槽位**，但 block 背景（boundingRect）只覆盖文字部分，多出的 60% 成为 block 之间的无背景白色空隙。而代码块（`<pre>`）内每个换行 `\n` 都被 Qt 解析为**独立 block**，于是每行之间出现一道白缝。

定量验证（block 间垂直空隙）：

| line-height | block 间白缝 |
|------------|-------------|
| 1.0 | 0 |
| 1.2 | 3.2px |
| 1.6（现状） | 9.6px |

### 10.2 修复

`wrap_html()` 的 `pre` 规则加 `line-height: 1.0;`：

```css
pre {
    background: #f4f4f4;
    padding: 12px;
    white-space: pre-wrap;
    line-height: 1.0;
}
```

代码块行距变为紧凑（代码块本就该紧凑），block 间空隙归零、背景连续。

### 10.3 测试

- 新增单元测试：`tests/test_code_wrap.py` 渲染多行代码块，断言各 block 的 `blockBoundingRect` 之间无垂直空隙。
- 现有测试回归。

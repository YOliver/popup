# 代码块长行自动折行 — 设计文档

- 日期：2026-09-29
- 状态：已实现
- 关联版本：v1.7.0

## 1. 背景与问题

用户反馈：Markdown 代码块（围栏代码）中的长行不随窗口宽度自动换行，超出窗口宽度的部分无法在预览界面中看到，只能靠水平滚动查看（截图可见水平滚动条），阅读体验差。

经排查，原因在 `wrap_html`（`md_viewer.py:1173`）的 `<pre>` 样式表：`pre` 只设置了背景和内边距，**未设置换行相关属性**。Qt 富文本引擎对 `<pre>` 块默认按 `white-space: pre` 处理——保留空白、不折行，因此超长行会溢出块宽度，产生水平滚动条。

对比：右侧编辑面板（`QPlainTextEdit`）默认 `lineWrapMode = WidgetWidth`，长行已能自动折行，与左侧预览行为不一致，正是用户感知到的差异。

## 2. 目标与非目标

### 目标

- 代码块（围栏/缩进代码块，含 `codehilite` 输出）中的长行随窗口宽度自动折行，不再出现水平滚动，窗口缩放时实时重排。
- 保留源码中的真实换行与空格（折行是软折行，不改变复制、搜索到的内容）。

### 非目标（YAGNI）

- 不在折行处显示续行标记（用户明确选择"自动折行"）。
- 不改动内联 `code` 的显示（内联代码本就允许换行）。
- 不做"是否折行"的开关配置。
- 不改动编辑面板行为（其已正确折行）。

## 3. 方案概述

在 `wrap_html` 的 `pre` CSS 块中追加 `white-space: pre-wrap;`，一行改动。Qt 富文本引擎自 Qt 5.14 起支持 `white-space` 属性（`normal` / `pre` / `nowrap` / `pre-wrap`），本项目使用 PySide6（Qt 6.x），满足要求。`pre-wrap` 语义为"保留空白与换行、遇块边界自动折行"，与浏览器一致，正符合需求。

## 4. 详细设计

### 4.1 改动点（仅 `md_viewer.py`）

`wrap_html` 的 `pre` 样式块（`md_viewer.py:1173-1176`）由：

```css
pre {
    background: #f4f4f4;
    padding: 12px;
}
```

改为：

```css
pre {
    background: #f4f4f4;
    padding: 12px;
    white-space: pre-wrap;
}
```

### 4.2 关键细节

- **为何改 CSS 而非后处理 HTML**：`codehilite` 扩展输出 `<div class="codehilite"><pre>...</pre></div>`，围栏代码块输出 `<pre><code>...</code></pre>`，二者最终都落入 `<pre>` 元素，CSS 选择器 `pre` 一次性覆盖全部代码块，无需触碰渲染管线。
- **`pre-wrap` vs `pre`**：`pre` 保留空白但不折行（现状）；`pre-wrap` 保留空白且遇边界折行（目标）。`nowrap`/`normal` 会折叠空格、破坏代码排版，不采用。
- **实测验证（已完成）**：本项目此前经验表明 Qt 富文本的 CSS 子集有限（如 `text-indent` 只认 `px` 不认 `em`），故本方案在 offscreen 的 `QTextBrowser` 中实测确认。结果：渲染同一段超长代码块（窗口宽 300px），未加属性时水平滚动条 `maximum = 5230`、block 视觉行数 = 1；加 `white-space: pre-wrap` 后 `maximum = 0`、视觉行数 = 20，证明长行真实折行、水平滚动条消失。Qt 6 下该属性生效，无需备选方案。
- **软折行语义**：折行只发生在显示层，源文本不变，复制/文内搜索（`Ctrl+F`）拿到的仍是原始长行内容。

### 4.3 数据流

无新增数据流；`reload_file` 渲染管线不变，仅 `wrap_html` 输出的样式表多一条属性。

## 5. 边界情况

| 场景 | 预期行为 |
|------|---------|
| 围栏代码块内超长行 | 随窗口宽度折行，无水平滚动，缩放实时重排 |
| 缩进代码块（4 空格）内超长行 | 同上 |
| `codehilite` 高亮代码块 | 高亮 span 结构不受影响，长行同样折行 |
| 代码块内已有的真实换行 | 原样保留，不因折行而混淆 |
| 内联 `code`（非 pre） | 行为不变 |
| 普通正文段落 | 不受影响（正文本就走 Qt 默认折行） |

## 6. 测试计划

1. **offscreen 行为测试**（新增 `tests/test_code_wrap.py`，参照 `test_indent_rendering.py` 的 offscreen 模式）：渲染含超长行的围栏代码块到固定宽度（如 300px）的 `QTextBrowser`，断言：
   - `horizontalScrollBar().maximum() == 0`（无水平溢出，守护用户核心目标）；
   - 代码块所在 block 的视觉行数 > 1（长行真实折行，而非被裁剪）。
2. **单元测试**：`wrap_html` 为纯函数，断言其输出样式表含 `white-space: pre-wrap`（字符串级守卫，防止样式被误删）。
3. **手动视觉冒烟**：打开用户截图对应的长句文件，确认代码块长行折行、水平滚动条消失、缩放窗口实时重排、复制与 `Ctrl+F` 搜索仍为原始内容。
4. **回归**：确认无代码块文档、标题、列表、引用、表格、图片显示均不受影响（本改动只加一条 CSS，风险面极小）。

## 7. 影响分析

- 改动集中在 `wrap_html` 的 `pre` 样式一条属性，不触碰渲染管线、目录、搜索、托盘、编辑面板、全局热键等模块。
- 不引入新依赖、不新增类或方法。
- 仅影响 `<pre>` 块的换行行为，其余文档渲染完全不变。
